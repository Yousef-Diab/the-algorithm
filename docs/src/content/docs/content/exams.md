Each section can have two optional review artifacts, both independent of each
other: a **revision summary page** (`summary.html`) and a **final exam**
(`exam.js`). `section.js` is required if either exists.

## The summary page (`summary.html`)

Authored like a lesson but with:

- `id="{sid}-review"` (e.g. `s1-ict-core-review`),
- `data-kind="review"`,
- a `<div class="review-footer"></div>` slot instead of `.lesson-footer`.

```html
<section class="lesson" id="s1-ict-core-review" data-kind="review" data-title="…">
  <div class="lesson-hero">
    <div class="crumb">Revision</div>
    <h2>ICT Core — Summary</h2>
    <div class="desc">…</div>
  </div>
  <!-- re-statement of the section's lessons -->
  <div class="review-footer"></div>
</section>
```

**It re-states the existing lessons; it never adds new material** — the
source-material rule applies (see [Content Rules](/content/rules)).

## The final exam (`exam.js`)

Same shape and authoring rules as `quiz.js`:

```js
[
  {q:"question?",o:["opt0","opt1","opt2","opt3"],a:1,e:"explanation from the notes"},
  …
]
```

Exactly 4 options, `a` = 0-based index, options shuffled at render time,
option lengths balanced, correct option + `e` traceable to the source.

## The exam page

The exam **page** is generated by the route
`src/pages/course/[section]/exam.astro` — there is no `exam.html` to write.
The page and its question count regenerate themselves from `exam.js`.

Behavior:

- It grades **nothing until Submit** is pressed.
- It scores against an **80% pass mark**.
- It **can be retaken**.
- Results are stored per section in `ict-exam` (best/last/taken/picks, picks
  by option text since options re-shuffle) — see
  [Client State](/architecture/client-state).

## Review/exam pages are excluded from lesson data

Pages carrying `data-kind` are excluded from:

- `LESSONS`,
- the lesson count,
- the progress bar,
- the notes boxes.

This keeps review/exam pages from distorting progress tracking.

## verify.mjs checks

The verification suite checks that:

- review + exam pages render,
- the exam scores on submit (full answers → 100% pass),
- the retake works,
- the question count each `summary.html` states in prose **matches the exam
  that actually renders** (a summary may state no count; it may not state a
  wrong one).

## Adding or upgrading an exam

1. Edit that section's `exam.js` (the array literal).
2. Rebuild + verify: `pnpm build` && `pnpm verify`.
3. If the question count changed, update the prose count in `summary.html` if
   it states one.
4. Update `CHANGELOG.md` (`### Changed`/`### Added`).
